### 🚀 快速启动

#### 方式1：演示模式（Mock平台，无需真实USB Key）

```powershell
# 1. 修改配置为用户模式 + 启用Mock平台
$cfg = Get-Content "c:\USBKey\config\config.json" | ConvertFrom-Json
$cfg.usermode = $true
$cfg.platform = @("mock")
$cfg | ConvertTo-Json -Depth 10 | Set-Content "c:\USBKey\config\config.json"

# 2. 启动管理端
Start-Process "c:\USBKey\src\USBKey.Manager\bin\Release\net8.0-windows\USBKey.Manager.exe"
```

**演示功能**：
- 自动检测到1台模拟设备（Serial-USBKey 演示设备）
- PIN登录：`123456`
- 预置2个模拟证书可查看/导出/注册
- 可导入PFX、修改密码、重置设备等全流程演示

#### 方式2：管理模式（需生成授权）

```powershell
# 1. 启动管理端（第一次会弹出授权激活）
Start-Process "c:\USBKey\src\USBKey.Manager\bin\Release\net8.0-windows\USBKey.Manager.exe"

# 记录显示的机器码，例如：A1B2C3D4-E5F67890-12345678-9ABCDEF0

# 2. 启动授权终端生成license
Start-Process "c:\USBKey\src\USBKey.LicenseTool\bin\Release\net8.0-windows\USBKey.LicenseTool.exe"
# - 输入机器码
# - 勾选平台（mock / lnca）
# - 设置有效期（默认1年后）
# - 生成授权 → 复制JSON

# 3. 返回管理端，粘贴授权JSON，点"保存并验证授权"
# 验证通过后即可使用全部管理功能
```

### ⚠️ 重要说明

#### 关于LNCA真实设备对接

当前状态：
- ✅ **DLL加载框架已完成**：可通过序号导出解析`JIT_USBKEY_HD.dll`（44导出，序101-144）
- ✅ **设备枚举已实现**：通过WMI按VID/PID枚举LNCA设备
- ⏳ **接口签名待确认**：具体函数原型需要：
  1. 实物LNCA USB Key设备
  2. IDA Pro（您提到的MCP）
  3. 逆向分析序号导出的函数参数/返回值/调用约定

**当前行为**：选择真实LNCA设备并执行操作时，会抛出`NotSupportedException`并提示：
```
该操作对应的驱动接口签名尚未完成逆向对接，需在实体设备 + IDA 环境下确认后填入（见 LncaOrdinals）。
```

**对接位置**：
- `src\USBKey.Core\UsbKey\LncaProvider.cs` — 主接口实现
- `src\USBKey.Core\UsbKey\LncaApiMap.cs` — 序号映射常量
- `src\USBKey.Core\Native\NativeDll.cs` — 底层DLL加载

**对接方法**：
1. 用IDA Pro打开`c:\USBKey\Library\LNCA\JIT_USBKEY_HD.dll`
2. 逆向分析序号101-144各函数的签名（例如序104可能是Login，参数为设备句柄+PIN字符串）
3. 在`LncaProvider.cs`中填充委托定义并调用`TryBind<委托类型>(序号)`
4. 重新编译即可

#### 安全承诺

本软件**绝不提供任何破解接口**：
- ❌ 不导出私钥
- ❌ 不提供无凭据解锁/改密（所有操作必须PIN/PUK/AdminKey认证）
- ✅ 接口层设计已排除破解能力（见`IKeyProvider`接口定义）
